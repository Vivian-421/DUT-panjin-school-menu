# 菜单自动同步

同步器只处理`菜单/八一.md`、`菜单/八二.md`、`菜单/美食广场.md`、`菜单/第三食堂.md`。仓库README及其他文件由维护者编辑，自动同步保留它们。

公开菜单与个人记录分别保存。程序不读取个人记录，也不调用模型判断或改写菜单。

- 沙箱修改：与上次同步内容比较后，自动提交到main。
- 线上修改：维护者合并PR后，自动写回沙箱公开菜单。
- 双方修改：对照上次同步的原文进行三方合并；独立修改合并，同一处冲突创建待审PR，保留沙箱原文与线上main，暂停同步等待维护者处理。
- PR合并或关闭：按线上最终版本恢复同步；等待审核期间产生的新编辑继续保留并参与三方合并。
- 无变化：不创建提交或PR。错误退避，最长一小时后重试。

运行环境为Python 3.10以上及Git。Token从服务器私有文件读取，需要本仓库Contents及Pull requests读写权限；Token和同步状态不放进公开仓库或沙箱。

首次运行前，公开目录必须与远端一致；以`--initialize`建立同步基线。后续运行省略该参数。

```sh
python3 tools/sync_menu.py \
  --root /path/to/食堂 \
  --state /private/path/state.json \
  --token-file /private/path/token \
  --status-file /path/to/食堂/同步状态.md
```

`--owner UID:GID`可指定沙箱文件属主。服务器使用systemd每两分钟执行一次；程序只读写公开菜单及状态文件，不重启聊天服务。

验证：`python3 -m unittest discover -s tools -p test_sync_menu.py -v`。

参考[peter-evans/create-pull-request](https://github.com/peter-evans/create-pull-request)：采用有变更才提交、待审PR复用的思路；本项目用服务器定时服务直接访问GitHub，冲突PR由维护者手动处理。
